# Dotfiles

Personal development environment, managed declaratively with **Nix** —
[nix-darwin](https://github.com/nix-darwin/nix-darwin) for macOS system config and
[home-manager](https://github.com/nix-community/home-manager) for the user
environment. A single [flake](./flake.nix) drives every machine.

## Supported platforms

- **macOS** (primary, Apple Silicon) — nix-darwin + home-manager + declarative Homebrew for GUI casks.
- **Linux / WSL2** — standalone home-manager on top of the existing distro.

Everything shared (shell, git, tmux, CLI tools) lives in `home/` and is imported by
both platforms; macOS-only bits (system defaults, casks, fonts) live in `hosts/darwin.nix`.

## Install (fresh machine)

```sh
git clone https://github.com/marksie1988/dotfiles.git ~/repos/dotfiles
cd ~/repos/dotfiles
./setup/bootstrap.sh
```

`bootstrap.sh` installs Nix (Determinate Systems installer, flakes enabled) — or, if
Nix is already present from a distro package, enables flakes and starts the daemon —
installs Homebrew on macOS, and runs the first activation. SSH/GPG keys are **not**
managed by Nix — generate them once if needed (the script prints the commands).

The clone location isn't fixed: `bootstrap.sh` builds from wherever you cloned. If
that's **not** `~/repos/dotfiles`, set `dotfiles.repoPath` (see [`home/options.nix`](./home/options.nix))
so the `dfup` helper and the live Neovim config symlink point at the right place.

Your username is auto-detected from `$USER` (which is why the commands below pass
`--impure`), so nothing in the flake is hardcoded to a specific account.

## Daily use

The update model is explicit and reproducible (no more on-shell-launch auto-pull):

```sh
# Apply local changes to the flake:
darwin-rebuild switch --impure --flake ~/repos/dotfiles#Stevens-MacBook-Pro   # macOS
home-manager switch  --impure --flake ~/repos/dotfiles#linux                  # Linux/WSL2

# Both are wrapped in the `dfup` shell function.

# Update pinned inputs (nixpkgs etc.), then rebuild:
nix flake update
dfup
```

`flake.lock` pins exact versions — that's what keeps machines from drifting.

## Layout

| Path | What |
|------|------|
| `flake.nix` | Inputs + `darwinConfigurations` / `homeConfigurations` outputs. |
| `setup/bootstrap.sh` | Fresh-machine bootstrap. |
| `hosts/darwin.nix` | nix-darwin: macOS defaults, Homebrew casks, fonts, Nix settings. |
| `home/` | home-manager modules: `options` (feature flags), `packages`, `cli`, `zsh`, `git`, `tmux`, `neovim`, `npm-globals`, `vscode`, `ghostty`. |
| `config/` | Verbatim config files (starship, k9s, helix, bat, nvim) symlinked by home-manager. |

This repo is **standalone** — clone it and it builds with no private dependencies.
Private/personal config is kept out of here in separate private repos: a Nix overlay
(`dotfiles-priv`, e.g. SSH config with internal hosts) that wraps this one, and
`dotfiles-agents` (AI agent instructions + Claude skills). Keep secrets out of this repo.

`herdr` (agent multiplexer) is installed via Homebrew (`hosts/darwin.nix`); the Ghostty config is generated by `home/ghostty.nix`.
| `SHORTCUTS.md` | Full alias / keybinding reference. |
| `NIX.md` | How the Nix setup works + how to change it (start here). |

## Secrets / local overrides

Machine-specific secrets go in `~/.env.local` (gitignored), sourced by zsh at startup:

```sh
export ANTHROPIC_API_KEY=...
export GITHUB_TOKEN=...
export TMUX_AUTOSTART=1   # opt in to tmux auto-attach
```

## Verifying changes

```sh
nix flake check                                                   # evaluate all outputs
darwin-rebuild build --impure --flake .#Stevens-MacBook-Pro       # build WITHOUT activating
nix fmt                                                           # format all .nix files
pre-commit run --all-files                                       # nixfmt + statix + deadnix + shellcheck
```

CI runs `nix flake check`, a formatting check, and shellcheck on push / PR
(`.github/workflows/lint.yml`).
